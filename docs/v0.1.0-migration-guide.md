# v0.1.0 migration guide

## Scope

Version 0.1.0 is the initial supported release of
`docx-comment-extractor`. There is no prior supported version to migrate from.

The pre-release package exported a placeholder `hello` function. Version
0.1.0 removes that export and provides the document extraction API described
below.

## Command-line interface

Install the package and run the extractor with an input Word document:

```bash
docx-comment-extractor INPUT.docx [--output OUTPUT.md]
```

The module entry point remains available:

```bash
python -m docx_comment_extractor.cli INPUT.docx
```

Without `--output`, Markdown is written to standard output. With `--output`,
the Markdown is written to the requested file and a success summary is written
to standard error. Input validation and extraction failures produce a non-zero
exit status.

## Python API

Import the supported API from the package root:

```python
from pathlib import Path

from docx_comment_extractor import (
    ExtractionError,
    extract_document,
    render_document,
)

result = extract_document(Path("draft.docx"))
markdown = render_document(result.document)
```

`extract_document` returns non-fatal issues in `result.warnings` and raises
`ExtractionError` when the Word package cannot be loaded. The rendered result
uses inline [CriticMarkup](https://criticmarkup.com/) highlights and comments.

## Output and limitations

The extractor preserves paragraph order, maps Word heading styles to
hash-prefixed Markdown headings, and keeps comment ranges that span paragraphs
open across the rendered blank line. Multi-paragraph comment bodies are joined
with ` / `.

Top-level tables are skipped with a warning. Footnotes, tracked changes, text
boxes, and images are not extracted in version 0.1.0.
